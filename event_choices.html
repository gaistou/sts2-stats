Event choices

For the handful of Act 1 events where the two branches leave a distinguishable signal in the data (damage taken, or an HP change), how does picking one over the other correlate with Act 1 clear rate and full-run winrate? Most events can't be split this way — the raw data only has the event's name and what came out of it, not the literal choice text — so this page covers only the events confirmed to have a reliable per-branch signal.

Methodology

Every row reads the literal branch a run took directly off the game's own data (event_choices[-1].title.key) rather than inferring it from a side effect like damage taken. No landmark-floor restriction: this compares two branches of the same single decision point, once a run has already reached the event -- every run that ran into it at all is one observation.

All 5 characters combined per row (stratified and weighted per character, then combined -- same technique as every other report on this site). Each row shows two bars: Global winrate (the decisive outcome -- did this run go on to win the whole game, not just this act) and Act 1 (did it clear Act 1), each independently naming whichever choice comes out ahead on that metric and by how much. They often name the same choice, but not always -- a choice can help a run survive Act 1 more often while still hurting its overall win chance, or vice versa, and both bars are shown every time specifically so that split is visible instead of hidden behind a single number. Bars share one fixed scale (10 points = full-width) across every row and both metrics, so magnitudes are comparable at a glance.

Events with more than two meaningful branches, or where a branch is itself a multi-step escalating choice (e.g. "keep going or bail" repeated several times), aren't shown here -- a single with/without split can't represent them without hiding real structure.
